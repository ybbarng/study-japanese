# 써 보기(획순 쓰기 연습)

가나 레슨의 쓰기 단계와 `/kana/write` 써 보기 화면이 같은 부품으로 돈다. 부품은 가나를 따로 알지 않고 "글자 → 쓰는 차례대로 늘어선 획 경로" 데이터만 있으면 돈다. 그래서 한자나 다른 문자(키릴 문자, 태국 문자 등)도 데이터와 글자 묶음만 더하면 같은 화면으로 연습한다.

## 어디에 무엇이 있나

- 획 데이터: `src/lib/writing/data/*.json`(아래 "데이터 꼴")
- 글자 묶음: `src/lib/writing/sets.ts`(꼴), `kana-sets.ts`(히라가나·가타카나), `registry.ts`(묶음 목록과 필요한 글자만 받는 `loadStrokes`)
- 판정: `src/lib/writing/stroke-check.ts`(획 하나·다 쓴 글자의 순서·방향), `counts.ts`(획 수와 다른 꼴 예외), `layout.ts`(칸에 늘어놓기)
- 화면 부품: `src/components/writing/`(본보기 그림·획순 애니메이션·캔버스·써 보기 화면)
- 가나에만 있는 것: 두 꼴 예외 표 `src/lib/kana/strokes.ts`, 진도 기록 `src/components/kana/kana-write.tsx`

## 데이터 꼴

출처가 KanjiVG가 아니어도(다른 공개 데이터, 직접 만든 획) 이 꼴로 넣는다.

```json
{
  "source": "자료 이름과 주소",
  "copyright": "저작권 문구",
  "license": "라이선스와 가공 내용",
  "viewBox": 109,
  "chars": {
    "글자": ["M10,20c5,0,10,0,20,0", "M50,10l0,80"]
  }
}
```

- `viewBox`: 글자 한 칸의 한 변. 경로 좌표가 0~viewBox 안에 있다. 파일마다 달라도 화면이 109로 맞춘다.
- `chars`: 글자마다 SVG path의 `d` 목록. **배열 차례가 쓰는 차례, 경로가 나아가는 방향이 쓰는 방향**이다. 판정은 이 둘만 본다.
- 직접 만들 때는 SVG 편집기에서 획마다 쓰는 방향으로 선(path) 하나를 그리고 쓰는 차례대로 `d`를 늘어놓는다. 채우기 윤곽이 아니라 붓이 지나가는 가운데 선이어야 한다.
- 손으로 쓸 때 다른 획 수로도 쓰는 글자(き를 3획으로)는 데이터를 고치지 않고 묶음의 `alternates` 표에 적는다. 다른 꼴로 쓰면 획 수만 받고 획마다 순서·방향은 보지 않는다.
- 남의 자료면 `src/lib/sources/registry.ts`에 출처를 먼저 적는다(docs/standing-rules.md "자료 출처와 공개 범위"). 자유 이용 허락 자료는 `license`를 함께 적는다.

## 새 문자를 더하는 법

1. 데이터 파일을 위 꼴로 만든다.
2. `WritingSet`을 하나 만든다: 이름, 문자 이름(`script`), 글줄 방향(`direction`), `lang`, 출처 id, 행(이어서 연습할 글자 줄), `has`(이 묶음 글자인지), `load`(데이터 받기).
3. `registry.ts`의 `WRITING_SETS`에 더한다. 써 보기 화면의 묶음 고르기에 저절로 나온다.
4. 진도를 남기려면 `WritingItem.recordId`를 주고 화면 쪽(`kana-write.tsx` 같은 곳)에서 기록한다.

## 한자로 넓힐 때 할 일

기본은 **KanjiVG 전체를 넣고, 화면은 그때그때 필요한 글자만 받는 것**이다.

- 받을 것: KanjiVG 릴리스의 `kanjivg-YYYYMMDD-main.zip`(2026-07-14판 12.6MB, 글자 6,703개 SVG). 변형 꼴(`-Kaisho` 등)이 든 `all.zip`은 쓰지 않는다.
- 뽑기: 가나와 같은 방법으로 SVG의 `<path id="kvg:XXXXX-sN" d="…">`를 `sN` 차례로 모으고 숫자를 소수 한 자리로 줄인다. 줄일 때 `-0.01`처럼 빼기 부호가 숫자 구분 노릇을 하던 값이 0이 되면 앞 숫자와 붙으므로 빈칸으로 가른다(가나 뽑기에서 ぱ·も가 깨졌던 일).
- 나누기: 가나처럼 묶음 파일 하나로 두지 않고 **글자마다 파일 하나**로 나눈다. 예: `public/strokes/kanji/65e5.json`(글자 코드). 한자 묶음의 `load(chars)`는 넘겨받은 글자의 파일만 받는다. 정적 파일이라 서비스 워커에 캐시 규칙을 하나 더한다.
- 크기 예상: 가나 162자가 44KB(글자당 약 270바이트)였다. 획 하나가 100바이트 남짓이므로 한자를 평균 10획 남짓으로 잡으면 글자당 1~1.5KB, 6,703자 전체가 7~10MB쯤이다(뽑아 본 값이 아니라 어림). 글자마다 나누면 한 화면이 받는 것은 그 글자 몇 KB뿐이다.
- 오프라인: 강을 받아 둘 때 그 강에 나온 한자의 획 파일만 함께 받아 둔다. 전체를 미리 받지 않는다.
- 글자 묶음: 교재 강마다(일무따 N강에 나온 한자) 행을 만들고, 행 이름은 강 이름으로 한다.
- 라이선스: KanjiVG는 CC BY-SA 3.0이라 뽑은 파일도 같은 라이선스로 둔다. 출처는 이미 `kanjivg`로 등록돼 있다.
- 판정 허용 범위(`STROKE_RULES`)는 가나 기준이다. 획이 짧고 많은 한자에서 너무 엄격하거나 느슨하면 묶음마다 다른 값을 넘기게 바꾼다.

## 판정 규칙

- 획 하나: 그은 선과 본보기 획을 길이가 고르게 16점으로 다시 찍어 차례가 같은 점끼리의 평균 거리(칸 한 변에 대한 몫)를 본다. 본보기 위에서 0.16, 빈 칸에서 0.24 안이면 같은 획이다. 뒤집은 본보기가 0.75배보다 가까우면 방향이 거꾸로, 다른 차례의 획이 0.75배보다 가까우면 순서가 틀렸다. 칸 한 변의 10%보다 짧은 획(탁점 등)은 방향을 보지 않는다.
- 다 쓴 글자(레슨 쓰기): 그은 획 수가 데이터와 같을 때만 획끼리 견준다. 그은 획 전체를 본보기 상자에 맞춘 뒤 빈 칸 기준(0.24)으로 보고, 순서·방향이 다른 획만 틀렸다고 한다(자리·모양은 겹침 채점이 본다).
