# 노래 분석 (세션이 따를 순서)

사용자가 "이 노래 분석해 줘"라고 하면 Claude 세션이 이 순서대로 분석 파일을 만들어 서버에 올린다. 분석 파일이 있으면 가사 학습 화면(`/songs/<slug>`)에 후리가나, 낱말을 누르면 나오는 뜻, 줄마다 문법 메모가 붙는다.

## 지킬 것

- **분석 파일에는 가사 글자를 넣지 않는다.** 줄은 차례(`index`)와 지문(`hash`)으로, 낱말은 줄 안 글자 위치(`start`, `length`)로 가리킨다. 화면 글은 사이트가 DB의 가사에서 잘라 만든다.
- `pnpm songs:pull`로 받은 가사 파일(`content/songs/<slug>.lyrics.json`)은 **읽기만 한다.** 그 안의 `ja`를 분석 파일·대화·커밋·저장소 어디에도 옮겨 적지 않는다. 옮겨 적는 것은 `index`·`hash`뿐이다.
- 가사 전체를 매끄럽게 옮긴 번역은 만들지 않는다(저장소 규칙 "자료 출처와 공개 범위"). 줄 해석(`ko`)은 관리자가 직접 붙여 넣는 칸이고, 세션은 채우지 않는다.
- `content/songs/`는 git 밖이다(`.gitignore`, pre-commit이 막는다). 커밋하지 않는다.
- 운영 서버에는 GET(`songs:pull`)과 rsync로 분석 파일 올리기만 한다.

## 순서

1. **가사 받기**
   ```bash
   pnpm songs:pull <slug>          # 운영(https://study-ja.byb.kr)에서
   pnpm songs:pull <slug> --url http://localhost:3457   # 다른 주소(환경 변수 SONGS_URL도 된다)
   ```
   가사를 공개한 노래는 로그인 없이 받힌다. 비공개 노래는 `STUDY_PASSWORD`를 주면 로그인해서 받는다. 결과 파일의 줄마다 `index`, `hash`, `chars`(글자 수, 코드포인트), `ja`가 있다.
2. **분석 파일 쓰기**: `content/songs/<slug>.json`을 아래 모양으로 쓴다.
3. **확인**
   ```bash
   pnpm songs:check <slug>          # 스키마·지문·위치·빠진 줄
   pnpm songs:check <slug> --show   # 위치가 가리키는 낱말과 뜻을 줄마다 찍는다(위치를 잘못 셌는지 볼 때)
   ```
   "맞음: 모든 가사 줄에 분석이 있다"가 나올 때까지 고친다. 결과는 가사 글 없이 줄 차례로만 알린다.
4. **서버에 올리기**
   ```bash
   rsync -av content/songs/<slug>.json byb.kr:data/study-ja/content/songs/
   ```
   화면이 요청 때마다 파일을 읽으므로 재배포 없이 바로 보인다. 가사 파일(`<slug>.lyrics.json`)은 올리지 않는다.

## 분석 파일 모양

스키마 정본은 `src/lib/songs/analysis.ts`(zod)다. 모르는 필드는 거부한다.

```json
{
  "slug": "<slug>",
  "analyzedAt": "2026-11-23",
  "lines": [
    {
      "index": 0,
      "hash": "1a2b3c4d",
      "tokens": [
        { "start": 0, "length": 1, "reading": "そら", "pos": "名詞", "gloss": "하늘" },
        { "start": 2, "length": 4, "reading": "みていた", "base": "見る", "pos": "動詞", "gloss": "보고 있었다" }
      ],
      "grammar": [
        { "pattern": "〜ていた", "explain": "…하고 있었다. 지난 일이 이어지던 모습.", "ref": { "book": "ilmuta", "lesson": 12 } }
      ]
    }
  ]
}
```

위 예의 낱말은 지어낸 줄 "空を見ていた"를 가리킨다.

| 필드 | 뜻 |
|---|---|
| `index` | 가사 줄 차례, 0부터. 가사 파일의 `index` 그대로 |
| `hash` | 그 줄 글의 지문(sha256 앞 8자리). 가사 파일의 `hash` 그대로. 가사가 바뀌면 지문이 달라져 그 줄은 분석 없이 보인다 |
| `tokens[].start`, `length` | 줄 안 글자 위치와 글자 수. **코드포인트 단위**(`Array.from(줄 글)`의 차례, 0부터). UTF-16 단위가 아니다 |
| `reading` | 히라가나 읽는 법. 한자가 든 낱말만. 노래에서 특별하게 읽는 한자는 노래의 읽기로 적는다 |
| `base` | 사전에서 찾을 기본형 한 낱말(겉모양과 다를 때만, 예: 降っても → 降る) |
| `pos` | 품사: 名詞·動詞·形容詞·形容動詞·副詞·助詞·助動詞·連体詞·接続詞·感動詞·代名詞 등. 화면이 한국어로 바꾼다 |
| `gloss` | 이 노래 맥락의 짧은 한국어 뜻(80자 안). 사전 뜻을 늘어놓지 않는다 |
| `grammar[]` | 줄의 문법 메모(줄마다 10개까지). `pattern`은 문형만(예: 〜ても, 30자 안), `explain`은 한국어 설명, `ref`는 그 문형을 배우는 교재 강(`ilmuta`/`ilmunta`, 강 번호) |

- 조각은 줄 전체를 덮지 않아도 된다. 뜻을 붙일 낱말만 두고, 덮지 않은 글자(조사·문장 부호 등)는 그냥 글로 보인다(누를 수 없다). 조사도 눌러 보게 하려면 조각으로 둔다.
- 조각은 앞에서부터 차례로, 겹치지 않게 둔다. 줄 글자 수(`chars`)를 넘으면 check가 알린다.
- 같은 글의 줄(후렴)은 한 번만 분석해도 된다. 사이트는 차례가 달라도 지문이 같은 분석을 쓴다. check도 그 줄을 빠진 줄로 세지 않는다.
- 뜻만 없고 문법 메모만 있는 줄은 `tokens`를 빈 배열로 둔다. 분석할 것이 없는 줄도 `{ "index", "hash", "tokens": [] }`로 적어 두면 "다시 분석해야 함"에서 빠진다.

## 무엇을 쓰나

- **gloss**: 그 노래에서의 뜻을 짧게. 낱말 설명 칸에서 가장 먼저 보이고, 아래에 네이버 사전 링크와 "일무따 n강에서 배움"이 함께 나온다.
- **grammar**: 학습자는 일무따를 진행 중이다. 이미 배웠을 쉬운 것(です·ます, 기본 조사)은 쓰지 않고, 모를 만한 것(노래에 자주 나오는 구어·문어 표현, 축약, 일무따 뒤쪽 강의 문형)만 쓴다. 교재 강을 확인할 수 있으면 `ref`를 단다. 화면에 "일무따 n강에서 배움 →" 링크(`/ilmuta/n`, `/ilmunta/n`)가 붙는다.
- **reading**: 노래에서 특별하게 읽는 한자(가사 표기와 다른 읽기)를 바로잡는 자리이기도 하다.

## 가사를 고쳤을 때

관리자가 가사를 고치면 글이 바뀐 줄은 지문이 달라져 분석 없이 보이고, 관리자 화면에 "가사가 바뀌어 n줄은 다시 분석해야 합니다"가 뜬다. 다시 `songs:pull` → 바뀐 줄만 고치기 → `songs:check` → rsync. 줄을 끼워 넣어 차례가 밀려도 지문이 같은 줄은 그대로 맞지만, check는 `index`가 어긋난 줄을 알리므로 `index`도 고쳐 둔다.
