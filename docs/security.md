# 보안

study-ja.byb.kr의 위협 모델, 2026-11-24 점검 결과, 남은 위험을 적는다. 비밀 값은 적지 않는다.
누가 무엇을 할 수 있는지의 정본은 docs/standing-rules.md "자료 출처와 공개 범위"다.

## 지킬 것과 막을 사람

| 지킬 것 | 누가 볼 수 있나 | 막을 사람·사고 |
| --- | --- | --- |
| 학습 기록 쓰기·내보내기, 사이트 설정, 노래 넣기·고치기 | 관리자(암호를 아는 사람)만 | 방문자, 암호 대입, 다른 사이트에서 보낸 요청(CSRF) |
| 노래 음원(상업 음원) | 관리자만(고정) | 방문자, 경로 바꾸기 |
| 교재 오디오·소책자 글·자막(남의 자료) | 기본 공개, 출처마다 닫으면 관리자만 | 출처를 닫은 뒤 다른 길로 새는 것 |
| 서버 전송량(월 요금) | — | 교재를 되풀이해 받는 봇·뚫린 로그인 |
| 공개 저장소 | 누구나 | 비밀·교재 글이 커밋되는 것 |

막지 않는 것: 관리자 기기 자체를 뺏긴 경우, 서버(호스트)가 뚫린 경우.
IP로 사람을 나누지 않는다(공유 IP 뒤 정상 사용자가 피해를 보고, 공격자는 IP를 쉽게 바꾼다).

## 지금 막는 방법

- **로그인**: 암호 하나(`SITE_PASSWORD`)와 HMAC 서명 쿠키 `sj_session`(`HttpOnly`, 운영에서 `Secure`, `SameSite=Lax`, 180일). 서명 비교와 암호 비교는 걸린 시간으로 값·길이를 짐작하지 못하게 한다(암호는 SHA-256으로 같은 길이로 만든 뒤 비교).
- **대입 막기**: 사이트 전체에서 1분 안에 실패가 10번을 넘으면 10분 동안 모든 로그인 시도를 거절하고, 실패마다 0.8초 늦춘다(`src/lib/auth/lockout.ts`). 잠금 확인과 실패 기록 사이에 await를 두지 않아 한꺼번에 보낸 요청도 상한만큼만 확인된다. 암호 비교가 비동기가 되어 순서를 바꿨고, 순서가 틀어지면(30건이 모두 확인됨) 실패하는 시험으로 막았다(`src/app/api/login/route.test.ts`). 이미 로그인한 기기는 잠금과 상관없다.
- **권한 확인 두 겹**: `src/proxy.ts`가 관리자 화면과 `/api/*`의 쓰기 요청, `/api/export`를 먼저 막고, 각 라우트도 첫 줄에서 `rejectUnlessAdmin()`으로 다시 확인한다(`src/app/api/admin-routes.test.ts`). 노래 API는 원래부터 스스로 확인한다.
- **CSRF**: 쓰기 요청(GET·HEAD·OPTIONS가 아닌 것)은 `Sec-Fetch-Site`가 `same-origin`·`none`이 아니거나, 그 머리가 없을 때 `Origin`의 호스트가 다르면 403(`src/lib/auth/csrf.ts`). `SameSite=Lax`만으로는 같은 상위 도메인(`*.byb.kr`)의 다른 사이트가 보낸 POST를 막지 못해서 둔다. 두 머리가 다 없는 요청(curl·스크립트)은 남의 브라우저 쿠키를 싣지 못하므로 통과시킨다.
- **로그인 뒤 돌아갈 주소**: 사이트 안 경로만 받는다. `//`, `/\`, 제어 문자(탭·줄바꿈)는 첫 화면으로(`src/lib/auth/safe-next.ts`).
- **입력 검증**: 쓰기 API 본문은 zod로 검사하고 크기 상한을 둔다. 경로가 되는 이름(노래 slug·음원 파일 이름·자막 항목·상태 키)은 정규식으로 모양을 묶는다.
- **경로 순회**: `/media/*`는 조각마다 `..`·`/`·`\`·NUL을 거르고, 풀어 낸 위치가 미디어 폴더 안인지, 확장자가 mp3·m4a·pdf인지 본다(`src/lib/media/resolve.ts`). 깨진 %인코딩 주소는 proxy가 400으로 돌려보낸다(Next가 경로 값을 풀다 500을 내기 전에).
- **노래 음원**: `media/songs/`는 출처 목록에 없는 폴더라 관리자만 받는다. 노래 화면은 방문자에게 음원 파일 이름을 비워 보낸다.
- **출처 닫기**: 미디어(`/media`), 자막 API, 강·과 화면 데이터, 낱말 사전, 예문 낱말 누르기·확인 문제 재료, 노래 분석의 교재 연결, 가나 다리 레슨, 첫 화면에 실어 보내는 강이 모두 `visibleBooks()`/`canSeeSource()`를 거친다. 강 번호·제목·쪽수·오디오 목록은 닫아도 보인다(오디오 자체는 `/media`가 막는다). 오프라인 받기는 주소만 담고 실제 파일은 `/media`가 막는다.
- **전송량 상한**: 교재 오디오를 하루(한국 날짜)에 관리자 세션마다 3GB, 방문자 모두를 합쳐 3GB, 전체 6GB까지만 내보낸다(`src/lib/media/quota.ts`). 범위 요청도 실제로 보낼 바이트로 센다.
- **보안 머리**(`src/lib/security/headers.ts`, `next.config.ts`): 모든 응답에 `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, `Permissions-Policy`(마이크는 이 사이트만), 운영에서 `Strict-Transport-Security`. `/media/`를 뺀 화면에 CSP(`default-src 'self'`, `frame-ancestors 'none'`, `object-src 'none'`, `base-uri`·`form-action 'self'`, 바깥 연결 없음). `X-Powered-By`는 끈다.
- **검색엔진**: `robots.txt`가 모두 막고 화면에 `noindex`.
- **공개 저장소**: 교재 글·자막·오디오·노래 분석·DB·`.env*`는 `.gitignore`, 교재 오디오·PDF는 pre-commit(`scripts/guard-textbook-files.sh`)이 막는다.

## 2026-11-24 점검 결과

심각한 순. 모두 이 날 고쳤다.

1. **중간 — CSRF.** 같은 상위 도메인의 다른 하위 도메인 글에서 `text/plain` POST로 들은 기록(`/api/listen`)을 넣거나 로그아웃시킬 수 있었다. proxy에 출처 확인을 넣었다.
2. **중간 — 출처를 닫아도 소책자 글이 새던 두 곳.** 가나 다리 레슨(`/kana/read/<id>`)과 첫 화면이 실어 보내는 "바로 틀 강"이 공개 여부를 보지 않았다. e2e(`e2e/source-toggle.spec.ts`)로 막았다.
3. **낮음 — 보안 머리 없음.** 틀 넣기(클릭재킹)·MIME 추측·`X-Powered-By` 노출. 위 머리를 붙였다.
4. **낮음 — 권한 확인이 proxy 한 겹뿐.** 빌드한 앱에서 `//api/…`, `/%61pi/…`, `/api/%65xport`, `/%73ettings` 같은 주소 바꾸기는 모두 308·401·404로 막혔지만, 앞으로 경로 규칙이 바뀌어도 새지 않게 라우트에도 확인을 넣었다.
5. **낮음 — 암호 길이가 걸린 시간으로 드러날 수 있었다.** 길이가 다르면 바로 돌아오는 비교였다.
6. **낮음 — 돌아갈 주소의 탭·줄바꿈.** `/\t/evil.example`은 브라우저가 탭을 지우고 `//evil.example`(다른 사이트)로 읽는다. 맞는 암호를 넣어야 일어나서 실제 위험은 작다.
7. **낮음 — 깨진 %인코딩 주소가 500.** 본문은 "Internal Server Error"뿐이라 정보는 새지 않았다. 400으로 바꿨다.

문제없음을 확인한 것: 세션 서명·만료 검사, 쿠키 속성, 로그아웃이 `Path=/` 쿠키를 지우는 것, 노래 음원·경로 순회(빌드한 앱에 여러 인코딩으로 시험), 자막 항목·노래 slug 모양 검사, `dangerouslySetInnerHTML` 없음, git 이력의 비밀 모양(AWS 키·개인 키·GitHub 토큰·Slack 토큰·`SESSION_SECRET=`·`SITE_PASSWORD=` 등, 건수만 셈: 0건), 교재·자막·노래·DB·`.env` 파일이 이력에 들어간 적 없음.

## 남은 위험

- **로그아웃해도 그 쿠키는 만료(180일)까지 유효하다.** 토큰을 서버에 적어 두지 않아서다. 기기를 잃어버리면 서버의 `SESSION_SECRET`을 새 무작위 값으로 바꾸고 다시 띄운다(모든 기기가 로그아웃된다). "모든 기기에서 로그아웃" 단추를 만들려면 서버에 세션 세대 값을 두어야 한다(사용자 결정).
- **잠금을 일부러 걸어 새 기기 로그인을 막을 수 있다.** 누구나 틀린 암호 11번으로 10분씩 잠글 수 있다. 이미 로그인한 기기는 영향이 없어 그대로 둔다. 대입 속도는 하루 약 1,500번이 상한이므로 **암호는 긴 무작위 값**이어야 한다(docs/DEPLOY.md).
- **CSP가 인라인 스크립트를 허용한다**(`'unsafe-inline'`). Next가 화면마다 인라인 스크립트를 싣기 때문이다. nonce를 쓰려면 화면마다 요청 때 그려야 한다.
- **방문자 오디오 몫을 한 사람이 다 쓸 수 있다.** 방문자 모두가 하루 3GB를 나눠 쓰므로, 누군가 다 받으면 그날 다른 방문자는 오디오를 못 받는다(관리자는 따로 센다). 서버 요금을 지키려는 의도된 모양이다.
- **방문자 화면에 관리자의 학습 기록이 보인다.** 강 지도·첫 화면·강 화면이 서버 DB(관리자의 들은 기록·문장 쓰기·가나 진도)를 방문자에게도 싣고, `GET /api/state/<키>`·`/api/writings`·`/api/listen`도 누구나 읽는다. "방문자의 진도는 그 사람 브라우저에만"과 어긋나고 관리자가 쓴 문장이 공개된다(사용자 결정: 방문자에게는 서버 기록을 싣지 않을지).
- **의존성 알려진 취약점**: `pnpm audit`은 네트워크가 필요해 이 점검에서 돌리지 않았다. Next 16.4.6·React 19.3.1로 최신이다(`pnpm outdated` 기준 뒤처진 것은 `@types/node` 하나).
- **오프라인 받기 묶음(`/offline/upcoming`)은 누구나 읽는다.** 강 제목과 오디오 주소만 담겨 있고, 고르는 기준이 관리자의 들은 기록이다.

## 점검할 때

- 공격 시험은 로컬 빌드(`pnpm build` 뒤 `e2e/serve.ts`)에서 한다. 운영에는 GET만 보낸다.
- 브라우저 시험: `e2e/security.spec.ts`(보안 머리·CSRF·미디어 경로), `e2e/source-toggle.spec.ts`(출처 닫기), `e2e/auth.spec.ts`(로그인·방문자 401).
