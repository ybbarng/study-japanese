# 저장소 규칙

사용자가 정했거나 지적한 규칙을 모은다. 같은 주제는 새 줄 대신 고친다. 처음엔 작게 두고 쓰며 키운다.

## 방향: 살아 숨쉬는 교재 (2026-11-23)
- 실제 교재에 준하거나 그보다 뛰어난 몰입감을 주는 사이트를 만든다. 몰입감은 꾸밈이 아니라 학습에 도움이 되어야 한다.
- 책보다 나은 점: 언제 어디서나 열리는 접근성, 그리고 다양한 상호작용. 소리·글·뜻·그림이 재생 위치에 맞춰 함께 움직이고, 누르면 반응하고, 내 기록에 따라 달라지는 교재.
- 화면을 만들 때마다 묻는다: 책으로 할 때보다 이해·기억·꺼내 쓰기에 무엇이 나아졌나? 강의를 들을 때는 실시간 자막·일본어·읽는 법·해석·낱말 카드·그림 같은 이해할 맥락을 준다.
- **PC도 폰과 같은 급으로 만든다(2026-11-23 사용자 지적).** 평일엔 폰으로 걸으며 듣지만, 주말엔 맥·집 윈도우에 앉아 문장 쓰기·일문따(종이책과 함께)·드릴을 한다. 넓은 화면에서는 폰 화면을 가운데에 좁게 늘어놓지 말고 넓이를 학습에 쓴다(예: 왼쪽 글·오른쪽 재생과 자막, 키보드 단축키, 실제 키보드로 입력). 화면을 만들거나 고칠 때 폰(412px)과 PC(1440px) 둘 다 본다.

## 운영에서 직접 확인한다 (2026-11-24 사용자 지적)
- 사용자가 써 보고 나서야 깨진 것을 아는 일이 없게 한다. 배포 뒤에는 운영 주소에서 실제 교재 데이터로 핵심 흐름(강의·예문 오디오가 받아지고 재생 위치가 늘어나는지, 자막이 따라가는지, 가나 소리, 노래 화면)을 확인한다. 가짜 데이터 E2E·맥 로컬 통과는 운영 동작의 근거가 아니다(맥은 한글 NFC·NFD를 같게 봐서 운영 404를 가렸다).
- 사용량 여유가 생기면 새 기능보다 운영 점검과 학습자 눈으로 써 보기를 먼저 한다.
- 요구를 계획(docs/plan.md)·보고에서 "끝"으로 표시하기 전에 학습자 기준으로 확인한다: 기능이 "있다"가 아니라 덮은 비율(예: 낱말의 몇 %에 그림)과 운영 실제 화면(폰·PC)으로 본다. 운영 학습자 점검 서브에이전트 결과를 끝 판정에 쓴다(2026-11-24, 오디오 404·그림 30%가 "있음"으로 끝 처리됨).

## 브라우저로 확인할 때 (2026-11-23)
- 시험용 Chrome·Chromium은 `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream`으로 띄운다(맥에 마이크 권한 창이 뜨지 않게). Playwright는 playwright.config.ts에 들어 있다.

## 진행 방식 (2026-11-23)
- 단계에 날짜를 정하지 않는다. `docs/plan.md` 순서대로 쉬지 않고 이어 가서 최대한 빨리 완성하고, 사용자가 전체를 써 보게 한다. 실제 학습은 2027-01부터.
- 사용자가 요청한 것을 서브에이전트에 맡겼으면 "아직 사이트에 반영되지 않음"과 지금 어디까지인지를 차례마다 분명히 적는다(2026-11-23 PC 화면을 세 번 묻게 함). 눈에 띄는 부분부터 먼저 배포한다.
- 차례를 끝낼 때도 다음 단계 서브에이전트나 백그라운드 일을 띄워 두어 일이 멈추지 않게 한다. 사용자 결정을 기다리는 일은 책상에 두고, 그것에 묶이지 않은 다음 단계를 먼저 한다.

## 자료 출처와 공개 범위 (2026-11-23 사용자 결정)
- 이 사이트는 앞으로 **여러 출처의 자료**를 모은다. 남의 자료는 `src/lib/sources/registry.ts`에 출처(이름·저작권자·원래 주소·저작권 문구·media 폴더·책 이름)를 먼저 적고 들인다. 출처를 적지 않은 자료는 저절로 공개되지 않는다(관리자만).
- 화면에 남의 자료를 보일 때는 출처 표시(`SourceCredit`)를 붙이고, **그 자료의 저작권이 권리자에게 있다**고 적는다.
- 일무따·일문따 오디오·소책자는 출판사(길벗)가 무료로 공개한 자료다(산 것이 아님). 다시 배포할 권한은 없고, 문제가 되면 그때 닫는다.
- **사이트는 누구나 쓸 수 있게 연다(FTF 방식).** 학습 기록 저장·수정·내보내기와 설정은 암호를 아는 사람만. 방문자의 진도는 그 사람 브라우저에만 남는다.
- 노래(상업 음원): 재생은 로그인한 사람만(고정). 가사 학습 화면은 공개(2026-11-23 사용자 결정). 가사는 사용자가 사이트에 직접 붙여 넣는다. 세션은 가사 전문을 가져오거나(가사 사이트·자막·받아쓰기) 대화·파일·요청 본문에 다시 쓰지 않는다. 이것은 사용자 규칙이 아니라 Claude의 기본 제약이다. 가사 분석(읽는 법·낱말 뜻·문법 메모)은 세션이 해서 git 밖 분석 파일로 서버에 올린다(2026-11-23 사용자 결정). 분석 파일에는 가사 글자를 두지 않고 줄 순번·지문·글자 위치만 둔다(docs/song-analysis.md).
- 남의 자료도 기본은 공개다. 로그인한 사람이 설정 화면(`/settings`)에서 **출처마다** 즉시 닫을 수 있다(닫으면 로그인한 사람만). 검색엔진 수집은 막는다(noindex·robots.txt). 로그인하지 않은 방문자 전체의 오디오 전송량은 합쳐서 하루 상한을 둔다.
- 오디오·원본은 git에 넣지 않는다(`media/`, `textbook-src/`는 `.gitignore`, `scripts/guard-textbook-files.sh`가 pre-commit에서 막는다). 서버 폴더에 둔다.
- **저장소는 공개다(2026-11-23 사용자 결정).** 교재에서 뽑은 글(`content/textbook/`)·자막(`content/transcripts/`)·잘라 낸 오디오(`media/`)는 git 밖에 두고, 서버에는 rsync로 옮긴다(docs/DEPLOY.md). 테스트 고정 데이터·문서·커밋 메시지에도 교재 문장을 옮겨 적지 않는다(모양만 같은 가짜 문장을 쓴다).

## 커밋 나누기 (2026-11-23)
- 사이트 개발 커밋: 작은 의미 단위마다 바로 커밋한다. 메시지 머리는 `feat:`·`fix:` 같은 종류를 쓴다.
- 학습 기록 커밋: `study/` 아래(문장 쓰기·진도·점검)는 학습 세션이 끝날 때 묶어 커밋하고 메시지 머리는 `study:`로 한다.

## 세션이 못 하는 일은 처음에 밝힌다 (2026-11-23 사용자 지적)
- Claude 제약 때문에 못 하는 일(예: 가사 전문 가져오기·옮기기·통째 번역)은 일을 받는 첫 답에서 ① 무엇을 못 하는지 ② 사용자 규칙이 아니라 Claude 제약이라는 것 ③ 대신 할 수 있는 방법을 말한다. 법적 판단 같은 다른 논의로 흐려 두지 않고, 그 제약에 묶인 설계 선택은 이유를 함께 밝힌다.

## 세션과 나누는 말
- 사용자는 아직 일본어를 모른다(2026-11-24). 읽는 법·표기·뜻이 맞는지 판단을 사용자에게 넘기지 않는다. 세션이 정해서 고치고, 사용자 손이 꼭 필요하면 "어느 화면 몇 번째 줄 몇 번째 글자를 무엇으로 바꾸기"처럼 그대로 따라 할 수 있게 적는다.
- 지금은 한국어 위주다. 일본어로 이야기하는 방식은 2분기나 3분기쯤 사용자와 정해 들인다.
- 일본어 오류 종류(조사 は/が/を/に, 활용·정중체, 자타동사, 한자 읽기, 악센트)는 쓰면서 정한다.

## 코드 품질 (2026-11-23)
- 의존성은 최대한 최신 안정판을 쓴다. 새로 들일 때 최신을 고르고, 단계가 끝날 때마다 `pnpm outdated`로 뒤처진 것을 올린다(pnpm 공급망 검사를 통과하는 범위).
- 가독성과 구조: 화면(app)·부품(components)·순수 로직(lib)을 나누고, 로직은 화면 밖 순수 함수로 떼어 테스트한다. 파일 하나가 한 가지 일을 하게 하고, 길어지면 나눈다.
- 테스트를 잘 쓴다: 전역 테스트 원칙을 따른다. 단위 테스트는 `src/**/*.test.ts(x)`, `pnpm test:run`. 핵심 화면 흐름(로그인·재생·기록)은 브라우저 E2E로 따로 묶는다.
